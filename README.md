# Title: Macandala

# Team Members: Daniel Aguilar, Pardis Roham

## Introduction
Macandala is a fun app that allows you to either create a mandala from scratch using
a wide range of pencils, or to generate one based on your birthday and color it!

## Software Requirements
To run Macandala, the user needs Java 21 or later. To manage dependencies and
access packages such as kilt-graphics, an internet connection is needed for the
first run of the program. In an editor such as Visual Studio Code, the Gradle
extension must be installed for this to occur. Finally, it is necessary to verify
that image files, originally stored in the .res folder, are accessible to the editor
or terminal when running the project.

The main class of the app is located in the file "MacandalaApp.java". After running
the main method, a window showing a main screen with colored stones in the background
and two white buttons should appear. If this does not occur, the user should verify
that previous software and file requirements are met, as well as the <ins>exactly named</ins> packages
"axisSystem", "brushesAndSlider", and "mandalaGenerator". If the user clicks
the button that reads "Create Your Own", they will be prompted to a drawing screen with
many tools and sliders to make a mandala. On the other hand, if they click on "Generate
Your Own", the program will ask them to provide a seed number and then display an
autogenerated mandala that can be painted using bucket tools.

## Limitations and Bugs
- **User input**: The user can currently input numbers that are not a birthday date as long as they
are integers. A future version of the project could improve both the interface and the verification
of user input.
- **Generator**: Because the size of shapes is randomized to some extent, parts of them sometimes go
beyond the canvas size for certain seed numbers. While this was minimized, it occasionally occurs.
Moreover, shapes overlap and their perimeters intersect; an extension
of the generator could attempt to fuse elements to create more stylized mandalas.
- **Eraser**: The eraser deletes shapes close to the mouse coordinates using a set size
to sweep elements surrounding the point. Very small
sizes struggle to erase some shapes.
- **Tools UI**: The user currently cannot preview the size of tools when painting, nor personalize them.
This goes beyond the scope of this project.
- **Color and sliders**: Sliders currently do not depict values for the size or RGB channels.
- **Buckets**: In the drawing screen, buckets are unable to detect color gradients for brushes with
variable opacity, ultimately setting plain fill and stroke colors. Additionally, the buckets depend on size
to paint generated mandalas; overlapping shapes might be painted at the same time
as there currently is no layer system.
- **Painting limits**: Brushes are still capable of overlapping slightly over the mandala layer limits, depending on the
click location and brush size. This could be fixed by allowing the user to paint near borders such that
parts extending beyond the canvas are simply hidden by other graphic groups.
- **Screen resizing**: The program does not react to the resizing of the window; it remains the same as the initial
program run. While some features are capable of being resized, such as the color sliders,
a resizing feature for every graphic element goes far beyond the project scope.
- **Window screenshot**: The user is not able to pick where to save their screenshot; it is saved directly
to the project folder. Moreover, if the user saves a new mandala, the previous save will be
overwritten. A future version could also determine how to save the image so that only the mandala
is shown, rather than the full UI.
- **Factorization**: While the project successfully divided the app logic into many classes, some still
require further factorization, such as the button systems for both the drawing screen and input screen.
An extension of the project could potentially improve the code further, include classes for visual testing,
and implement defensive programming logic for certain variables.

## Societal Impact Acknowledgements
While our project does not have the intention or potential to harm vulnerable populations,
we acknowledge that it has certain limitations, excluding certain populations
and drawing on cultural elements of significance for some groups. The program does not have
system modes to facilitate usage for people with visual impairments, such as color-blindness or blindness.
Also, access to a computer is required; not everyone has access to a laptop, and the program is not set
to be used on other devices, such as phones. Finally, mandalas and specific designs are tied
to spiritual practices, traditions, and beliefs of various religions, such as Buddhism. While
we did not intend to appropriate these symbols, we recognize their cultural weight. This project is
purely educational and non-commercial. We do not intend to modify the sacred symbolism of these
designs for profit, but rather to explore the intersection of geometry, a fun project, and code.
